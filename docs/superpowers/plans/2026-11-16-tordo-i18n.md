# Interface Languages (es, en, pt-BR) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tordo's interface in Spanish, English and Brazilian Portuguese, chosen from the browser or once per installation, with English URLs, API vocabulary, logs and CLI.

**Architecture:** A small translation layer in the web app (`web/src/lib/i18n/`: one message module per language, `t(key, params)` with `Intl.PluralRules`, a reactive locale). The server stores the installation's language in `config.json` and exposes it on `/api/auth` and `/api/status`; it answers errors as `{code, message, params}` so the web translates them. One English vocabulary replaces the Spanish URL/API words, with a store migration for saved stations.

**Tech Stack:** Go (stdlib + `modernc.org/sqlite`), Svelte 5 runes, Vite, Vitest. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-16-tordo-i18n-design.md` (read it with this plan; section numbers below refer to it).

## Global Constraints

- No new Go or npm dependencies; no cgo.
- `go test ./...` and `(cd web && npm test)` pass with no network after every task.
- Commit messages: never add `Co-Authored-By:` trailers (CLAUDE.md overrides any default attribution).
- Read-only on the music collection; only `config.json`, `tordo.db`, `cache/` are written.
- Locales: exactly `es`, `en`, `pt-BR`. `en.js` is the reference key set.
- Spanish messages copy today's Spanish text **verbatim** (voseo: "podés", "activá"), so existing Spanish assertions keep passing.
- Number formatting locale: `es` → `es-AR`; `en` → `en`; `pt-BR` → `pt-BR`.
- Genre and style names are never translated (Discogs names).
- The Vitest setup file sets the locale to `es` before every test file; tests that check other languages call `setLocale` themselves and restore `es` in `afterEach`.

## Review Focus

1. **Odd browser languages** (`navigator.languages` undefined, empty, `['zh-CN']`, `['PT']`, `['pt-PT','en']`): resolves to a supported locale (English when nothing matches), never throws. Test in Task 2.
2. **Odd `language` values in `config.json`** (`"fr"`, `"pt-br"`, `"EN"`, a number): unknown means automatic and the server still starts; known ones in another case are canonicalized (`"pt-br"` → `"pt-BR"`). Test in Task 1.
3. **Saved stations that are malformed, already in the new vocabulary, or mixed**: the migration leaves malformed JSON and new-vocabulary definitions byte-identical, never fails opening the catalog, and running twice is a no-op. Test in Task 6.
4. **Error bodies that are not JSON** (a proxy's 502 HTML, an empty 500, a text body from a handler that was missed): the UI shows the body text or `t('error.http', {status})`, never `[object Object]` or a key. Test in Task 9.
5. **A phone on a different automatic language than the computer** receiving Rockola notices: the notice is shown in the phone's language. Test in Task 9.
